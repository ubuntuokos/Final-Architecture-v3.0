## Single conversion facade: five explicit modes

A shared typed conversion interface extends #195's existing `file.convert.inspect`, `file.convert.plan`, `file.convert.execute`; status and cancellation are UAF/Temporal task observations, not duplicate independent executors. Device-intensive operations use existing HRB CPU/memory admission and optional explicitly assigned accelerator leases.

1. `PROBE_ONLY`: inspect format, source app/version, media digests, in-file references, manifest; no untrusted macro/script execution.
2. `PREVIEW_ONLY`: render or read a lossy/one-way projection, visibly tagged non-editable, without adding a symmetric import pair to the admit list.
3. `BIDIRECTIONAL_SUBSET`: explicitly admitted same-type input/output subset with external-source golden fixtures, independently verified semantic equivalence, loss matrix and receipt.
4. `DELIVERY_ONLY`: output master/proxy/PDF/WAV/stems/IMF; does **not** declare the project itself migrated.
5. `HYBRID_LINK`: approved immutable local source snapshot with explicit cross-app reference graph, separate read-only sync permissions, no silent writeback.

WASM suitability is decided for *exact* format pairs and packaged pinned worker digests/SBOM. Native remains first choice for large FFmpeg/RAW/scene operations and for any pair with validated native-only semantics. CPU-only baseline is mandatory; no automatic display-GPU enrollment, no remote conversion, no silent route switch.
