## Objective and product boundary

The user must be able to (1) link a production that stays in an external app, (2) transfer an editable production into the existing FA3 application family, (3) import selected parts of multiple productions into a single existing FA3 Production Graph, (4) preserve and audit originals without destructive conversion, or (5) keep a hybrid production with an explicitly authorized, version-scoped optional sync bridge. Supported production profiles must remain Story/Screenplay-owned: feature, television film/series, commercial, live broadcast, documentary, news, animation, music video, interactive, and custom.

**No new project authority, scheduler, asset registry, conversion daemon, video editor, provider router, model gateway, approval authority, evidence store, secret authority, resource broker, transfer engine, or desktop app.** Production Import & Migration is a composable capability and GUI workspace of the existing FA3 Director/Production Studio, Creative Project Workflow, Asset Graph, Tools/Conversion, Document Fabric, Audio/Video/3D Fabric, and FA3 Logistics.

Native `.fa3video`, `.fa3clip`, Story branch/revision model, `.fa3character`, `.fa3motion`, `.fa3pose` and all external originals are preserved. External interchange is not internal source authority. A flat MP4, PDF, WAV, or FBX is never represented as equivalent to the full editable original project.

## Capability interface and production graph

Define a versioned subordinate **ProductionImportPlan**/Receipt schema linked to the existing `FA3-CREATIVE-PROJECT-WORKFLOW-CONTRACTS-001` CreativeProjectGraph (CAP-171 source preservation), typed Tools `file.convert.*` actions, existing Asset Graph and `FA3-UNIFIED-ACTION-FABRIC-001`.

Each source `ProductionSourceManifest`: source application and version; production type; source URI/path in authorized local scope; source project digest; immutable snapshot and read-only original; file manifest; file hashes; relative paths; media technical facts; external links; unknown/untrusted objects; rights and license; user-selected target project and owner; provenance. Gather only minimum needed metadata; never upload manuscripts or media to cloud without explicit approved provider action.

Each `ImportCapabilityMatrix` is **per exact source version, destination version, format pair, direction and semantic feature** (e.g., track/edit/cut, nested compound, transition, motion effect, timebase, audio plug-in state, subtitles, commentary, author/revision, materials/shaders, color space, BWF bext). Outcomes: `EXACT`, `PARAMETRIC_EQUIVALENT`, `LOSS_DECLARED`, `EXTERNAL_LINK_ONLY`, `INSPECT_ONLY`, `UNSUPPORTED`. Unknown is UNSUPPORTED; a pair is not admitted merely because a donor advertises file-extension support.

Typed operations: `discover -> probe -> inspect -> immutable_stage -> construct_preview -> classify_loss -> plan -> explicit_approval -> bounded_execute -> independent_verify -> commit_or_rollback`, plus `cancel/progress`. No user-facing claim of successful production import before target app and cross-app handoff checks pass. Destructive import, unapproved external writeback or implicit flattening is forbidden. Every import yields machine-readable `ProductionImportReceipt` with source/target digests, source and target application versions, converter identity/digest and exact feature-level results, license/security/HRB/UAF/approver refs, reverse-export result, relink map, task dependency validation and external immutable source snapshot.

## Unified GUI (no new app shell)

**Production Studio → Open / Import Production** with four modes: LINK_ONLY, COPY_EDITABLE, HYBRID and ARCHIVAL_COPY. Six tabs, sharing existing Qt6/QML Control Center:
1. **Sources:** point at projects/export bundles, optional on-LAN peer via FA3 Logistics; show detected app/version/type, no source mutation.
2. **Structure:** tree of scenes/episodes, story branches, shots, tracks, assets, notes, reviews and job dependencies with unique ID conflict resolution.
3. **Compatibility:** per-format/feature exact/parameterized/loss/external/inspect/unsupported matrix, current version and pair gates; no fake “100% compatible”.
4. **Targets:** select existing FA3 project/apps, source-of-truth preference for conflicts, machine-role plans and missing plug-in/media handling; HRB resource preflight.
5. **Approval:** privacy/license and destructive/cost/writeback disclosures; require explicit sign-off for loss and task-scope expansion.
6. **Execution / Verification:** progress, pause/cancel/resume using UAF + Temporal; file manifests, application open tests, native roundtrip where admitted, receipts, repairable defects and rollback. Editors may access imported artifacts only after commit.

Expose a second entry point in existing **Tools → Conversion** for single files or batches, backed by the SAME specialized adapters/format-pair matrix; offer an explicit “Add to Production” action, never silently create a project.

## Threat model, hardware and coexistence

Untrusted input types include archive XML/JSON/AAF, macros, embedded media, scripts, deserializers, external USD/reference paths and network URIs. Fail closed on path traversal, symlinks escaping staging, zip/tar bombs, decompression bombs, malicious LaTeX and font/plugin loaders, media parser defects, log-injection and prompt-injection in imported source text, unmanaged host mounts, unapproved network egress, partial overwrite and symlink collisions. Archive extraction requires isolated per-job workspace, canonical path resolution, object/byte/count/depth/time limits, permission normalization and independently calculated hashes. Imported comments and scripts remain **data**, not AI tool instructions. Preserve source-side approval/provenance as attributable claims, not automatic FA3 authorization.

Before any actual execution: preflight Reuse Discovery + Donor Registry, source licensing and security, Software Coexistence & Host Non-Interference retroactive audit, Hardware Audit, Security Governance approval, HRB authoritative CPU/memory/resource lease; optional GPU/NPU only with task- and model-scoped authorization. Zero accelerator CPU path mandatory, no vendor-specific baseline, no hardware-parameter mutation, no implicit display-GPU enrollment. Linux distro-generic packaging, Wayland-first / X11-fallback GUI. Remote or billable services require explicit per-task authorization; no paid commercial runtime dependency. All provider selection by existing deterministic governed route, model calls via Model Router; no silent fallback.
